# igdump

[English](README.md)

Выгружает посты Instagram в HTML-архив, а комментарии и пользователей, поставивших лайк —
в HTML со статистикой и CSV для Excel.

## Установка

Нужны Python 3.11+ и Google Chrome для выгрузки постов.

```console
pip install -r requirements.txt
```

Для отдельного окружения и установки команды `igdump`:

```powershell
# Windows (PowerShell)
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e .
igdump -h
```

```bash
# Linux / macOS, из папки проекта; Python 3.11+
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
igdump -h
```

Онлайн-режимы `posts` и `full` используют установленный Google Chrome.
Для первого входа нужно графическое окружение. `--offline` не запускает браузер.
На Linux/macOS запуск проекта пока не проверялся на реальных системах.

В Windows CMD активация выполняется командой `.venv\Scripts\activate.bat`.
Для проверенных версий зависимостей внутри окружения используйте
`python -m pip install -c requirements-tested.txt -e .`.
Отдельное окружение предотвращает конфликты с другими OSINT-инструментами.

## Команды

### Надёжность и обновление данных (0.6)

- Завершённый архив при следующем онлайн-запуске проверяет свежую голову ленты
  и соединяет её с сохранённой историей. Незавершённый сбор продолжает сохранённый
  курсор. Старые публикации сохраняются: архив не является зеркалом удалений.
- Порядок определяется точным временем публикации, когда оно известно, включая
  закреплённые посты. При неизвестных датах выводится предупреждение. Сбор последних N
  может завершиться раньше только при известных датах, признаках закрепления
  и хронологическом порядке обычных постов; иначе обходится вся лента.
- HTTP 200 с ошибкой API или без обязательного списка считается ошибкой,
  а не успешным пустым результатом. Отсутствие картинок мест по-прежнему допустимо.
- Посты и страницы комментариев сохраняются в `.posts.sqlite` и `.comments.sqlite`.
  Старые JSON мигрируют автоматически. HTML/JSON постов обновляются примерно раз
  в 10 секунд и при штатном завершении; каждый пост сразу фиксируется в SQLite.
  Офлайн-режим восстанавливает и записи новее последнего JSON-снимка.
- Смена выборки сохраняет архив аккаунта. Каталог защищён от двух одновременных
  CLI-запусков. Повреждённый JSON вызывает понятную ошибку и не стирается.
- Полные данные медиа из ленты используются до открытия отдельных страниц постов.
  При неполных данных или истёкших ссылках сохраняется запасной путь через Chrome.
  Медиа скачиваются отдельной сессией без cookies Instagram и CSRF-заголовка.
  Существующие запасные пути получения публичного профиля сохранены.
- `igdump full "@username" --no-recheck-likes` отключает немедленную дополнительную
  проверку неполного списка лайков. По умолчанию одна перепроверка сохранена.
  Статус остаётся неполным; свежий счётчик может быть меньше старого кешированного.
- Лайки из кеша — архив наблюдений разных моментов, а не текущий снимок списка.
  `--refresh` заменяет выбранные списки; он также нужен для старых пустых результатов,
  которые предыдущие версии могли сохранить после ошибки API.
- Код завершения `4` применяется и к неполным офлайн-архивам/спискам участников.
  Создание HTML само по себе не означает, что собраны все выбранные данные.
- `Tracked HTTP requests` не включает запросы, которые Chrome выполняет внутри страницы.
  В диагностике появились времена фаз. Фильтры дат используют локальный часовой пояс
  компьютера экспорта; выбор зоны на графике не меняет выбранные публикации.

Команда выбирает содержимое: `posts`, `comments`, `likes` или `full`.
Опции выбирают публикации. Профиль принимается как `@username`, `username`
или ссылка `https://www.instagram.com/username/` (включая ссылки с параметрами).
Для установки команды `igdump` выполните `pip install -e .`; также можно
запускать `python insta_html_export.py`, как в примерах ниже.

```console
# Ссылка на профиль вместо имени — работает для всех команд
python insta_html_export.py full "https://www.instagram.com/kharlamova_alena/"

# Первые 100 постов с начала истории профиля, ранние сверху
python insta_html_export.py posts "@kharlamova_alena" --oldest --limit 100

# Последние 100 постов
python insta_html_export.py posts "@kharlamova_alena" --limit 100

# Все доступные посты, новые сверху
python insta_html_export.py posts "@kharlamova_alena"

# Комментарии / пользователи, поставившие лайк 100 последних постов
python insta_html_export.py comments "@kharlamova_alena" --limit 100
python insta_html_export.py likes "@kharlamova_alena" --limit 100

# Пользователи, поставившие лайк первым 100 постам
python insta_html_export.py likes "@kharlamova_alena" --oldest --limit 100

# Посты и обе статистики за 2024 год
python insta_html_export.py full "@kharlamova_alena" --after 01.01.2024 --before 31.12.2024
```

Для всех команд отсутствие лимита или `--limit 0` означает все посты.
`--limit N` выбирает последние N; `--oldest --limit N` — первые N.
`--oldest` без лимита выбирает все посты, ранние сверху. Даты применяются перед лимитом.
Для поиска первых постов нужен полный список публикаций. Если сбор списка
не завершён, скрипт сохраняет прогресс и останавливается; повтор продолжит сбор.
Старые команды поддерживаются: `all` означает `posts`, `oldest --limit N` —
`posts --oldest --limit N` (положительный лимит по-прежнему обязателен),
`likers` — `likes`. Подходящие старые папки кеша подхватываются автоматически.
Закреплённые посты могут влиять на порядок списка Instagram.

## Даты

Формат — **ДД.ММ.ГГГГ**, часовой пояс — как на компьютере.
Оба флага включают указанный день целиком. Отбор идёт по **дате публикации поста**,
а не по времени комментария или лайка. Лимит применяется **после** отбора.

```console
# С 1 января 2024 года включительно и дальше
python insta_html_export.py posts "@kharlamova_alena" --after 01.01.2024

# По 31 декабря 2024 года включительно
python insta_html_export.py posts "@kharlamova_alena" --before 31.12.2024

# Первые 100 постов внутри 2024 года
python insta_html_export.py posts "@kharlamova_alena" --oldest --limit 100 --after 01.01.2024 --before 31.12.2024
```

Эти флаги работают также с `comments`, `likes` и `full`. Ошибочные даты и обратный
промежуток не принимаются. Если дату поста определить не удалось, скрипт
останавливает отбор с объяснением, вместо того чтобы незаметно пропустить пост.
Полученные даты кешируются.

## Вход и результат

При первом запуске `posts` / `full` войдите в открывшемся Chrome и нажмите
Enter в терминале. Сессия сохранится для следующих запусков.

Для `comments` / `likes` скрипт может запросить cookie `sessionid`:
Chrome → F12 → Application → Cookies → instagram.com → sessionid.
Она сохраняется локально в `~/.insta-export/config.json`.

Результаты лежат в `exports/`, в папке с именем профиля, командой,
лимитом, признаком `--oldest` и фильтрами дат:

| Команда | Файлы |
|---|---|
| `posts` | `index.html`, локальные медиа |
| `comments` | `comments.html`, `comments.csv`, `comments-stats.csv` |
| `likes` | `likes.html`, `likes.csv`, `likes-stats.csv`, `likes-coverage.csv` |
| `full` | Все эти файлы, четыре пассивных отчёта ниже и общая страница `full.html` |

Готовый HTML открывается автоматически, в том числе при частичной выгрузке.
В консоли видны этап и шкала прогресса. Посты сохраняются по мере обработки;
повтор команды использует кеш и пробует загрузить пропущенные посты.
Завершённый кеш ссылок используется и при неизвестном общем числе публикаций.

Статистика комментаторов: число комментариев, охваченных постов, лайков
на комментариях и дата последнего собранного комментария. Статистика пользователей, поставивших лайк:
число собранных лайков каждого пользователя.
В HTML — верхние строки рейтинга; в CSV статистики — все собранные пользователи.
Top-10 постов использует сохранённые счётчики Instagram. Если в старом кеше
счётчика нет, число явно обозначается как собранное, а не общее.

Instagram может ограничить доступ или вернуть часть списка пользователей, поставивших лайк:
статистика описывает **полученные аккаунты**, а не гарантированно все лайки.
Ответы на комментарии могут не попасть в выгрузку. Неполный сбор обозначается.
При ошибке `429` подождите перед повтором. Отсутствие аватара не мешает выгрузке.

## Повторы и экономия в likes

`likes` не скачивает публикации, фотографии, видео или аватары. Собирает
ссылки и страницы пользователей, поставивших лайк. Завершённые списки берутся из кеша. При обрыве
соединения — максимум два дополнительных повтора; полученные страницы
сохраняются сразу. После `429` сбор останавливается.
При 429 от API профиля сначала используется запасной путь: публичный HTML
профиля через отдельную сессию с настольными заголовками, как в исходной версии.
Если запасной путь не сработал или ограничен сбор списка публикаций, `full`
прекращает следующие сетевые этапы, сохраняет кэш и диагностическую сводку.
Если список постов не получен, комментарии и лайки пропускаются, без повторного
сбора того же списка. Запрос с ответом HTTP 400 не повторяется без изменений;
для GraphQL возможен переход на REST, если известен числовой ID профиля.
После 429 подождите перед повтором: немедленный перезапуск не снимает лимит Instagram.
При сканировании постов ошибка `SSL EOF` в запросе профиля вызывает одну
резервную попытку через HTTP-клиент текущего контекста Playwright с той же
авторизацией. Проверка сертификатов остаётся включённой; ответ 429 от API
профиля на любом из этих запросов запускает тот же запасной путь через HTML.
Если публичный HTML перенаправляет на вход или не содержит ID профиля, сбор
постов читает профиль через уже авторизованный Chrome. Ответы со списком постов,
полученные Chrome, используются повторно. Обрывы соединения, SSL EOF и таймауты
при получении профиля также запускают этот запасной путь. Пагинация использует
параметры
реального GraphQL-запроса страницы и её сессию. Отсутствие картинок геолокаций
не делает корректный список публикаций непригодным.
Если запрос следующей страницы ещё не получен, Chrome прокручивает профиль,
чтобы получить актуальный запрос пагинации от Instagram. При переходе на REST
сбор начинается с его первой страницы, а сохранённые ссылки убирают повторы.
Курсоры GraphQL и REST разделены, в том числе при продолжении из кеша. Первая
полученная страница сохраняется до запроса следующей.
Запасной путь через HTML/Chrome также читает аватар и доступные поля нужного
профиля из встроенных данных страницы, метаданных или отображаемой фотографии.
Сохранённая заглушка заменяется, если следующий онлайн-запуск получил ссылку
на аватар.

42 из 43 означает, что Instagram вернул неполный список. Повтор может
найти недостающего пользователя, но полного списка API не гарантирует.
Полнота каждого поста видна в `likes-coverage.csv`. Неполные списки
автоматически перепроверяются один раз без отдельного флага. Сохранённые
неполные списки проверяются при следующем обычном запуске. Если добрать не
удалось, консоль, HTML и CSV покажут причину: нет следующей страницы или новых
пользователей, закончились сетевые повторы, доступ запрещён или ограничен.
Точную причину расхождения счётчика и списка API может не раскрыть. Запуск:

```console
python insta_html_export.py likes "@kharlamova_alena"
python insta_html_export.py likes "@kharlamova_alena" --offline
```

Сохраняйте прежние лимит, даты и папку результата. `--offline` пересчитывает
HTML/CSV из кеша: **без входа и запросов к сети**. Работает для всех команд.
`--refresh` заново собирает выбранные списки.

Кеш пользователей, поставивших лайк хранится в SQLite; старый JSON переносится автоматически и
остаётся резервной копией. Подсчёт делает база, CSV записывается постепенно.
Память зависит от размера страницы и числа уникальных пользователей, а не
всех лайков. При первом переносе старый JSON временно загружается в память.
Старые папки кеша и прежнее написание команды продолжают поддерживаться.

Запросы: проверка входа/профиля + страницы списка постов + страницы пользователей, поставивших лайк
необработанным или неполным постам, плюс одна проверка новых неполных списков. Отбор по датам может потребовать запрос на каждый пост
без сохранённой даты. `full` использует сессию Chrome и один отобранный список.
В обычном терминале прогресс закреплён внизу, логи — сверху. При перенаправлении
вывода в файл остаются редкие текстовые строки прогресса.

## Пассивные отчёты

В `full` по умолчанию включены четыре дополнительных отчёта. В других командах
включайте нужные флаги: `--analytics`, `--mentions`, `--contacts`, `--locations`.
Для отключения в `full` используйте `--no-analytics`, `--no-mentions`,
`--no-contacts`, `--no-locations`.

| Отчёт | Содержимое |
|---|---|
| `analytics.html` | Частота публикаций за наблюдаемый период, графики по месяцам, дням недели и часам, тепловая таблица «день × час» |
| `mentions.html` | Аккаунты, упомянутые через `@` в подписи или отмеченные на медиа; тип свидетельства и исходный пост |
| `contacts.html` | Телефоны, e-mail и ссылки из подписей; нормализованное значение, исходная подпись и ссылка на пост |
| `locations.html` | Названия мест, ID и полученные координаты; карта координат и исходные посты |

Каждый отчёт сохраняется в CSV и JSON. Файлы аналитики используют местный часовой
пояс компьютера, создавшего выгрузку. В HTML есть выбор часового пояса: по
умолчанию зона браузера, например `Europe/Moscow`. Переключение пересчитывает
даты, месяцы, дни недели, часы, тепловую карту и частоту локально, с учётом
летнего времени на дату публикации. Кнопки скачивают CSV и JSON выбранной зоны;
исходные файлы выгрузки не перезаписываются. Это время **публикаций**, а не активность аудитории.
Частота учитывает дни без постов между первой и последней известными публикациями
в выбранной выборке. Даты и лимит отбора применяются ко всем отчётам.
В таблице контактов ширины типа, значения, совпавшего текста и источника
фиксированы. Исходная подпись занимает оставшееся место и переносится; длинный
текст прокручивается внутри ячейки и не сжимает остальные столбцы.

Замеры скорости и исследование неполных списков лайков сохранены в
[диагностике сбора](docs/collection-findings.md).

Поля берутся только из ответов обычного скана и сохранённого кеша. Эти флаги
**не добавляют запросов** к Instagram, не проверяют чужие профили, не открывают
найденные ссылки и не запрашивают геокодирование. Офлайн-карта содержит контуры
стран Natural Earth (около 124 КБ), масштабирование, перемещение и маркеры
с исходными постами. У пинов указаны даты публикаций в локальном часовом поясе
компьютера экспорта. Нажатие показывает точное время со смещением UTC и ссылки
на посты. Одинаковые координаты объединены в пин с диапазоном дат. **Show pin dates**
включает и скрывает подписи на обеих картах. **Load street map (Internet)** включает подробную карту
OpenStreetMap: внешние тайлы загружаются только после нажатия. Leaflet хранится
локально (около 162 КБ). Отсутствующие даты, теги и места не
выдумываются: в отчётах указано покрытие. У старого кеша поля могут отсутствовать;
время из старых подписей дат отмечается отдельно. Контакт в тексте и упоминание
аккаунта сами по себе не подтверждают владельца или личность.

```console
# Сбор постов с дополнительными отчётами
igdump posts "@username" --analytics --mentions --contacts --locations

# Только перерасчёт по уже сохранённой папке, без сети и загрузки медиа
igdump posts "@username" --offline --analytics --mentions --contacts --locations --output-dir "exports/username-posts-0"

# Все отчёты из существующей полной выгрузки
igdump full "@username" --offline --output-dir "exports/username-full-0"
```

Все CSV защищены от формул Excel: перед потенциально исполняемым текстом
добавляется апостроф. Исходные значения в кеше и JSON не изменяются.

## Параметры

| Флаг | Что делает |
|---|---|
| `--limit N` | Последние N постов после отбора по датам; без лимита или 0 — все |
| `--oldest` | Первые посты, ранние сверху; работает для всех команд |
| `--after ДД.ММ.ГГГГ` / `--before ДД.ММ.ГГГГ` | Границы дат публикации, включительно |
| `--download-videos` | Скачивает видео для `posts` / `full`; без флага — только обложки |
| `--refresh` | Заново проверяет список постов и обновляет выбранные публикации / комментарии / пользователей, поставивших лайк |
| `--offline` | Пересчитывает отчёты из кеша без сети и входа; работает для всех команд |
| `--analytics` / `--mentions` / `--contacts` / `--locations` | Пассивные отчёты; в `full` включены по умолчанию, отключаются через `--no-…` |
| `--no-open` | Не открывает HTML автоматически |
| `--output-dir "C:\Archives\instagram"` | Своя папка результата |
| `--dry-run` | Отбирает и считает посты без загрузки медиа / комментариев / пользователей, поставивших лайк; требует доступа к Instagram |
| `--headful` | Оставляет Chrome видимым при выгрузке постов (`posts` / `full`) |
| `--batch-size N` | Карточки на порцию прокрутки HTML-архива (`posts` / `full`, по умолчанию 9); не меняет запросы API |
| `--browser-profile-dir PATH` | Сохранённый профиль Chrome для входа |
| `--sessionid COOKIE` | Cookie сессии для `comments` / `likes`; сохранённая сессия используется автоматически |
| `--comment-delay 3` / `--like-delay 3` | Задержка запросов соответствующей команды в секундах (по умолчанию 2) |
| `--verbose` / `--quiet` | Подробный / минимальный вывод |
| `-h` / `--help` | Общая справка: `igdump -h`; параметры команды: `igdump full -h` |

Параметры пишите после команды. Скачанные видео воспроизводятся в HTML,
в том числе в каруселях вместе с изображениями.
